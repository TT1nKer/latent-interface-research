# Transfer and expert selection across three domains

## Which use of the same action corresponds across people?

Two people assembled the same toy. Both picked up a screw several times. The screw pickup during the annotated step “attach body” was the **seventh of eight** pickups for one person and the **fifth of eleven** for the other. This is the first eligible pair and role in the sorted analysis, selected independently of each method's result. The fine action name alone does not distinguish these occurrences. [Source dataset](https://openaccess.thecvf.com/content/CVPR2022/html/Sener_Assembly101_A_Large-Scale_Multi-View_Video_Dataset_for_Understanding_Procedural_Activities_CVPR_2022_paper.html)

We grouped camera copies into physical demonstrations and matched the public fine and coarse Assembly101 annotations for 60 assembly recordings. Among 1,521 within-recording fine-action types that repeated inside coarse operations, 691 occurred under multiple coarse operation names. We then required a same-toy pair with different participants, two distinct roles for the fine action in each recording, and a specific role appearing precisely once for that action in both recordings. This yielded 212 directional tests across 34 pairs and 12 toys. These tests reuse recordings and are clustered by toy. [Source coverage](assembly101_coverage.json) · [Eligibility rules](assembly101_occurrence_screen_20261120.json)

For each test, a method receives the source marked occurrence and the two complete fine-action streams. Every target occurrence of the matching fine action can be selected, including events outside coarse action boundaries. The role labels are reserved for constructing and scoring cases. Uniform selection scored 13.32%, relative occurrence order 15.80%, and an edit-distance baseline matching the full sequences through each candidate 33.22%. Shared best scores receive fractional credit. Giving the 34 recording pairs equal weight yielded 12.75%, 14.17% and 33.04%. The comparison uses annotated action names, full future context and no pixels. It establishes a measurable task and a strong baseline. A claim about visual recognition or generalization to new toys requires a separate test. [Fixed comparator](assembly101_forced_alignment_protocol_20261120.json) · [Results](assembly101_alignment_results.json) · [Official annotations](https://github.com/assembly-101/assembly101-annotations)

A stricter post-hoc test holds both recordings and the fine action fixed, then swaps which of two source occurrences is marked. Both source marks must have distinct, uniquely corresponding target events. **30 unordered mark swaps from 16 recording pairs and eight toys** qualify. In 13 of the 30, the two required events occurred in opposite order for the two people. In every reversal the intervals were disjoint in both recordings, with at least 260 annotation frames between events. One person picked up a screw for the roller arm and later for the body; the other did those jobs in reverse. The 13 reversals span seven recording pairs and four toys. A single order-preserving map per recording pair can achieve both required matches on **at most 17/30** of these swaps. This bound does not apply to a matcher allowed to change its alignment with each cue, including independent forced-anchor alignments. The sample was selected for distinct observable roles and gives no prevalence estimate for arbitrary assemblies. [Paired swaps and example](assembly101_mark_swaps.json) · [Counting code](analyze_assembly101_mark_swaps.py)

On the stricter paired task, the previously fixed full-context edit matcher recovered both marks on 12.50% of the 60 directed swaps, including 22.06% of the 34 order-preserving cases and 0 of the 26 reversed ones. Fractions integrate over independent tie-breaking for the two cues. The uniform matcher averaged 2.75% overall. These are descriptive measurements on the same selected recordings. [Paired scores](assembly101_paired_scores.json)

We then specified one simple explanation for the failure on reordered events. At each occurrence, count the other nouns in the eight preceding and eight following fine actions. Compare these count vectors by cosine similarity, with no fit. This rule identified 58.73% of the 212 single marks, compared with 33.22% for anchored full-sequence edit distance. It solved both cues on 24/60 directed swaps, including 11/26 reversals from three toy designs. All 24 paired successes had unique top choices. This is an exploratory test on the panel whose baseline errors motivated the rule. Partial-label inputs and future context make it an annotation-level task. [Fixed rule](assembly101_part_context_20261120.json) · [Scores](assembly101_part_context_results.json) · [Independent confirmation design](assembly101_confirmation_20261120.json)

We froze the rules and tested all eligible records from another official split, excluding every discovery toy and participant ID before examining scores. This left 44 recordings, 24 toys and 11 participants. On 146 single-cue queries, other-part context scored **65.07%** and forced edit **38.01%**, a difference of 27.05 percentage points. In a descriptive breakdown, the part rule outscored edit alignment on eight of the nine eligible toy designs. [Toy-level counts](assembly101_confirmation_single_by_toy.json) Among the six directed, non-overlapping order reversals, the methods solved both marks in **5/6 and 0/6**. Those six directions came from just three physical recording pairs and two toys. The planned confirmation required eight toys and twenty recording pairs with reversals. It therefore remains inconclusive on the reversal primary, despite the positive estimates. A post-hoc time-direction check kept the source fixed and used only earlier target fine actions at each candidate. The single-cue score was 63.70% and dual marks were recovered on four of six reversal directions. All of these scores rank candidates offline from annotated streams. [Locked independent results](assembly101_confirmation_results.json) · [Cohort](assembly101_confirmation_source.json) · [Time-direction check](assembly101_time_context.json)

Temporal annotation transfer already appears in music synchronisation and in learned video alignment. Liu et al. explicitly address repeated, reordered actions. The open empirical question is whether a cue and evidence about the parts being assembled can recover **both** role-specific events when order reverses, and still locate ordinary events. The measured panel provides a feasibility check. Independent recordings and comparison with a nonmonotone method are needed before claiming a new result. [Liu et al., CVPR 2022](https://openaccess.thecvf.com/content/CVPR2022/papers/Liu_Learning_To_Align_Sequential_Actions_in_the_Wild_CVPR_2022_paper.pdf) · [Zalkow et al., AES 2017](https://www.audiolabs-erlangen.de/content/05_fau/assistant/zalkow/01_publications/ZalkowWPAM17_MeasureTransfer_AES.pdf)

## A second dataset changes which matcher wins

We carried the two fixed rules to HoloAssist, an independently collected dataset of egocentric physical procedures. We specified source selection, role labels and scoring before measuring coverage. Among 1,758 labeled recordings, 730 were selected in 365 non-reused recording pairs spanning 20 task types. We compared the two complete fine-action transcripts from recordings with the same task type. Reference roles were identified using structured coarse verb and noun labels. Individual performer identities could recur and are unavailable for the same disjointness check used on Assembly101. [Original dataset and paper](https://openaccess.thecvf.com/content/ICCV2023/html/Wang_HoloAssist_an_Egocentric_Human_Interaction_Dataset_for_Interactive_AI_Assistants_ICCV_2023_paper.html) · [Frozen design](holoassist_occurrence_transfer_20261120.json)

| Single marked occurrence | Eligible queries | Nearby parts | Full-sequence edit |
|---|---:|---:|---:|
| Assembly101 discovery | 212 | 58.73% | 33.22% |
| Assembly101 new toys and people | 146 | 65.07% | 38.01% |
| HoloAssist external | 710 | 67.68% | **80.85%** |

On HoloAssist, the edit matcher also solved both marks more frequently when their order was preserved (81.63% versus 55.28%, 142 directions). Only four physical recording pairs from four activities showed a qualifying strict reversal. The part rule solved two of eight directions; the edit rule solved zero. This misses the independently specified coverage floor. The rankings in the table concern offline localization from gold fine-action transcripts. [Measurements](holoassist_results.json) · [Evaluation code](analyze_holoassist_occurrence_transfer.py)

Candidate counts differ across datasets. Matching the exact distribution of candidate counts in a descriptive overlap analysis left an other-parts advantage of 26.58 percentage points on the Assembly101 held-out panel and an edit advantage of 2.77 points on HoloAssist. We used each common count's smaller frequency as its weight. This still leaves differences in annotation taxonomy, tasks, action order and participants. Benchmark identity or observed error patterns cannot be used as an advance estimate of the better matcher on a new task. [Count-stratified results and weights](candidate_count_results.json)

## Bidirectional image and text retrieval

A specialist can rank texts for an image and another can rank images for a text. We tested whether mixing them corrects complete groups of four decisions on BiVLC. We grouped 2,933 items by their 1,161 source photographs and held photographs intact across five folds. Each training fold selected the same TROHN-Img checkpoint in both directions. The held-out rule and this single model solved exactly the same 2,031 groups (69.25%). Across the 12 ordered pairs of distinct checkpoints we found 60 incompatible directional decision patterns among 35,196 item-pair combinations. For any fixed pair, even a perfect fallback restricted to these patterns could rescue at most 10 of 2,933 items.

With access to the answers, choosing a whole model per item would solve 2,303 groups. Allowing the two directions to choose different models would add 46 further groups (1.57 percentage points). These counts separate the opportunity for choosing an expert from the additional opportunity for combining their directions. They measure four related CLIP checkpoints. The published tables contain correctness bits rather than score margins, and an unsuccessful strict comparison can include a tie. We closed the cycle-triggered mixing rule on this panel. ## Solving equivalent linear programs

We analyzed 840 released solver trials for 30 linear programs, each written in four equivalent permutations and run with seven solver configurations. For each problem we compared two retrospective choices: its best single configuration across all four presentations and the best configuration separately for each presentation. Both choices achieved 100% verified solves. Mean charged CPU time fell from 0.180599 to 0.180339 seconds. For 29 of the 30 problems, at least one fastest configuration was shared across all four presentations. These are averages over a quick, single-machine panel with about 15.6 ms timing granularity in individual observations. On this evidence we closed the quick-panel selector. Hard mixed-integer or SAT instances could behave differently. ## Recompute from author data

The BiVLC fetcher needs Python with requests and PyArrow. Analysis also uses NumPy. The fetcher reads only the metadata portions of the two image-data shards and the authors' four prediction tables. The LP check uses the Python standard library and verifies the pinned table's SHA-256 before scoring.

```sh
python fetch_bivlc_direction_inputs.py /tmp/bivlc-scores
python analyze_bivlc_direction_cycles.py /tmp/bivlc-scores --out /tmp/bivlc-result.json
curl -fL https://raw.githubusercontent.com/h-a-forster/lpbench/cbd8a53ec250602eff4b53f4e583a4ad24856252/docs/results/quick/units.csv -o /tmp/lpbench-units.csv
python analyze_lp_permutations.py /tmp/lpbench-units.csv
```
